# Мастер озвучки (5 шагов)

BookVoice проводит пользователя через пять шагов для создания аудиокниги. Каждый шаг — отдельный экран с собственным ViewModel и валидацией. Переход к следующему шагу доступен только после успешного выполнения текущего.

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  1. Модель   │ →  │  2. Текст    │ →  │  3. Озвучка  │ →  │  4. Тембр    │ →  │  5. Экспорт  │
│  настройки   │    │  загрузка    │    │  синтез      │    │  (опц.)      │    │  метаданные  │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
```

## Шаг 1. Настройка модели

**ViewModel:** `ModelSettingsViewModel`
**View:** `ModelSettingsStepView`

### Что делает

Пользователь выбирает провайдер синтеза речи и настраивает подключение.

### Интерфейс

- **Выбор провайдера** — выпадающий список из шести вариантов
- **Для локальных провайдеров** (Silero, Kokoro, Qwen3 Local):
  - Индикаторы состояния: Python найден? → Зависимости установлены? → Сервер запущен?
  - Кнопка «Настроить» — последовательно выполняет все три этапа
  - Прогресс установки зависимостей
- **Для облачных провайдеров** (ElevenLabs, Qwen3 Cloud):
  - Поле ввода API-ключа
  - Кнопка проверки подключения
- **Для Custom API:**
  - Поля URL и порт
- **Системный промпт** — шаблон инструкций для озвучки (роль профессионального чтеца)

### Валидация

Провайдер выбран. Если локальный — Python доступен. Если облачный — API-ключ введён.

### Данные, сохраняемые в проект

`ttsProvider`, `apiURL`, `apiPort`, `elevenLabsAPIKey` / `dashscopeAPIKey`, `systemPrompt`

## Шаг 2. Загрузка текста

**ViewModel:** `TextUploadViewModel`
**View:** `TextUploadStepView`

### Что делает

Пользователь загружает текст и выбирает стратегию разбиения на сегменты.

### Интерфейс

- **Загрузка файла** — кнопка выбора .txt или .epub, либо перетаскивание (drag & drop)
- **Редактор текста** — можно вручную отредактировать загруженный текст
- **Стратегия сегментации:**
  - По предложениям — разделение по знакам `.` `!` `?`
  - По абзацам — разделение по пустым строкам
  - По главам — поиск заголовков («Глава», «ГЛАВА», римские цифры)
  - Фиксированная длина — указанное число слов
- **Превью** — первые 5 сегментов с нумерацией
- **Статистика** — количество слов, символов, примерная длительность

### Валидация

Текст не пустой, сегменты > 0.

### Данные, сохраняемые в проект

`sourceTextBookmark` (security-scoped), `segmentationStrategy`, `fixedSegmentLength`

## Шаг 3. Озвучка

**ViewModel:** `VoiceoverViewModel`
**View:** `VoiceoverStepView`

### Что делает

Синтезирует речь для каждого текстового сегмента. Основной рабочий шаг — здесь происходит генерация аудио.

### Интерфейс

- **Выбор модели** — список доступных моделей текущего провайдера
- **Выбор голоса** — если провайдер поддерживает (Silero: 6 голосов для ru, Qwen CustomVoice: 9 голосов)
- **Скорость и высота тона** — слайдеры (только для Silero/Kokoro)
- **Параметры генерации** (раскрывающийся блок, только для Qwen):
  - Temperature — случайность (0.6–1.5)
  - Top-K — ширина словаря (20–100)
  - Top-P — cumulative probability (0.5–1.0)
  - Repetition Penalty — штраф за повтор (1.0–2.0)
  - Max Tokens — максимальная длина вывода (100–2048)
  - Do Sample — использовать сэмплирование
- **Подсемплер** (только для Qwen Base — клонирование голоса):
  - Subtalker Temperature, Top-K, Top-P, Do Sample
- **Описание голоса** (только для Qwen VoiceDesign) — текстовое поле
- **Эмоция / инструкция** (только для Qwen CustomVoice и Cloud) — текстовое поле
- **Образец голоса** (только для Qwen Base) — выбор файла и текст образца
- **Список сегментов** — каждый показывает статус:
  - ⏳ Ожидание
  - 🔄 Синтезируется...
  - ✅ Готово (с кнопкой воспроизведения)
  - ❌ Ошибка (с сообщением)
- **Прогресс** — «Озвучено 12 из 45»
- **Кнопки** — «Озвучить всё», «Отменить», «Переозвучить неудачные»

### Как работает синтез

1. `VoiceoverViewModel.synthesizeAll()` итерирует по сегментам
2. Для каждого сегмента вызывает `LiveTTSService.synthesize(text, options)`
3. Сервис отправляет HTTP POST на `localhost:8100/api/tts`
4. Получает WAV-байты, сохраняет во временный файл
5. Обновляет статус сегмента и счётчик прогресса
6. При ошибке помечает сегмент как `.failed` и продолжает

### Валидация

Модель выбрана. Синтез не выполняется в данный момент.

### Данные, сохраняемые в проект

`ttsModelName`, `ttsSpeed`, `ttsPitch`, `ttsSpeaker`, `ttsEmotion`, `ttsLanguage`, `ttsTemperature`, `ttsTopK`, `ttsTopP`, `ttsRepetitionPenalty`, `ttsDoSample`, `ttsMaxNewTokens`, `ttsReferenceAudioBookmark`, `ttsReferenceText`, `ttsXVectorOnlyMode`, `ttsSubtalkerTemperature/TopK/TopP/DoSample`

## Шаг 4. Изменение тембра

**ViewModel:** `TimbreChangeViewModel`
**View:** `TimbreChangeStepView`

### Что делает

Опциональный шаг. Заменяет голос в синтезированном аудио через RVC (Retrieval-based Voice Conversion). Полезно, если хочется другой тембр, который нельзя получить напрямую от TTS.

### Интерфейс

- **Переключатель** — включить/выключить изменение тембра
- **Выбор модели** — файл .pth/.pt/.bin/.onnx с обученной RVC-моделью
- **Или профиль из библиотеки** — ранее сохранённый голос
- **Параметры:**
  - Index Rate (0.0–1.0) — степень влияния индексного файла
  - Filter Radius (0–7) — сглаживание медианным фильтром
  - Protect Voiceless (0.0–1.0) — защита безголосных звуков от искажения
- **Демо-превью** — конвертирует первый сегмент для прослушивания
- **Пакетная конвертация** — применяет ко всем сегментам

### Валидация

Если включен — путь к модели указан.

### Данные, сохраняемые в проект

`rvcEnabled`, `rvcModelBookmark`, `rvcIndexRate`, `rvcFilterRadius`, `rvcProtectVoiceless`

## Шаг 5. Экспорт

**ViewModel:** `PostProcessingViewModel`
**View:** `PostProcessingStepView`

### Что делает

Склеивает все аудиосегменты в один файл, добавляет метаданные и экспортирует.

### Интерфейс

- **Формат** — MP3, M4A, WAV, FLAC
- **Метаданные:**
  - Название
  - Автор
  - Альбом
  - Год
- **Обложка** — изображение (.jpg, .png) для встраивания в аудиофайл
- **Кнопка «Экспортировать»** — открывает NSSavePanel
- **Прогресс** — конкатенация и конвертация
- **Результат** — путь к файлу + кнопка «Открыть в Finder»

### Как работает экспорт

1. `LiveAudioEngineService.concatenate(urls, outputURL, format)` склеивает WAV-фреймы через `AVAudioFile`
2. Если формат не WAV, конвертирует:
   - MP3 → через `lame` (если установлен) или `afconvert`
   - M4A → через `afconvert` (встроен в macOS)
   - FLAC → через `afconvert`
3. `writeMetadata()` записывает ID3v2-теги (MP3) или freeform-атомы (M4A)
4. Отправляет системное уведомление об окончании

### Данные, сохраняемые в проект

`outputFormat`, `metadataTitle`, `metadataArtist`, `metadataAlbum`, `metadataYear`, `coverImageBookmark`, `outputFileBookmark`

## Навигация между шагами

`WizardViewModel` управляет переходами:

- `goToNextStep()` — сохраняет текущий проект → переходит к `currentStep + 1` → вызывает `prepareStep()`
- `goToPreviousStep()` — возвращает к `currentStep - 1`
- `goToStep(n)` — прямой переход (доступен только к ранее пройденным шагам)

`prepareStep()` обеспечивает передачу данных между шагами:

| Переход | Что происходит |
|---------|----------------|
| → Шаг 2 | Ничего — текст независим от провайдера |
| → Шаг 3 | `updateFromProject()` синхронизирует провайдер, загружает модели, подготавливает сегменты |
| → Шаг 4 | Передаёт URL-ы аудиофайлов из шага 3 |
| → Шаг 5 | `finalAudioURLs` = файлы из шага 4 (если включён) или из шага 3 |
